### 最硬的那一条：侦察卫星受控实验（2026-10-13）

协议（**全程没有任何单位移动** —— 这一点很关键，见第五节第 2 条）：

1. 拍快照 A（全内存，**含只读区**，0.2 秒）
2. 用户按一次**侦察卫星**（一次揭开一大片）
3. 8 秒后拍快照 B

时序已由用户界面截图确证：卫星是在 A、B **之间**按的。

差分结果（两级收紧）：

| 过滤 | 剩下 |
| --- | --- |
| 全部 ≥12 字节的连续变化 | 22,753 处（几乎全是画面缓冲区重绘） |
| 其中"前后取值都齐整" | **1 处** |
| 再要求"变之前整片是 `FF`、且两边还留着没被揭开的 `FF`"（用来剔掉新分配的内存） | **1 处** |

那唯一一处事后挖开：**周围已经又变回 `FF`** —— 是个用一下就清回的临时缓冲区。

⇒ **结论：如果黑幕是一张"一格一个数字、未探索统一一个值"的表，这个实验必然能看见它。看不见，就说明它不是。**

## 五、**判据本身**的三个硬伤（做这件事的人必须先看这一节）

这三条是 2026-10-13 一整天用真机换来的，**不看你就会重走**。

### 5.1 快照工具默认漏掉一整类内存

`tools\MemSnap.cs` 默认只收**可写**区域；带 `all` 才收只读区域。同一局实测：
默认 **520 区域 / 293 MB**，带 `all` **770 区域 / 363 MB**（差 250 区域 / 70 MB）。
它还会主动跳过**可执行**页 —— 老游戏的图形缓冲常被标成"可写又可执行"，那也是一块从没看过的地方。
**此前十几轮跑的全是默认档。**

### 5.2 ⚠ "找连续变化的一整段"这个判据，其实在测"有没有东西在动"

这是最大的一个坑，务必读完：

- "连续 ≥12 字节、同一拍朝同一方向变、前后取值齐整" —— 这套筛子**非常利**，539 MB 里只剩个位数处。
- 用户探路时它确实亮了 9 处，而且**只**在探路那 40 秒里亮。
- **但设计了一次辨别实验**：让用户**只在已经亮着的地方来回走、绝不探新地方** —— **照样亮 8 处，而且在同一片内存里**。
- ⇒ 它是**"有单位在动"的副产品**（单位动画 / 特效对象被创建），**不是"地图被点亮"的产物**。

**根因**：**新分配出来的一块内存整块都是同一个值**，在字节层面和"一整片格子一起翻转"**完全无法区分**。
**下一个人做任何"找整段变化"的判据，都必须先回答"这是新分配的内存，还是既有数据被改写"。**

### 5.3 别把"只出现一次"的候选丢掉

第一版差分报告只打印"出现过 ≥2 次"的候选，于是那次找到的 5 处**单次**现象被自己的报告扔掉、事后无法复查。
**负面结果也是数据。**

## 六、工具（都在 `tools\`，源码入库，`.exe` 不入库，用 csc 现场编）

编译：
```
C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe /nologo /codepage:65001 ^
  /platform:x64 /target:exe /out:tools\XXX.exe tools\XXX.cs
```

| 工具 | 能干什么 |
| --- | --- |
| `HousePeek.cs` | 只读探针。`resolve`（金钱链解出我方房子）/ `dump <addr> <len>` / `ptrs <base> <lo> <hi>` / `watch`（采样报告哪些字段在动）/ `slots`（盯生产流水线槽位） |
| `ShroudSweep.cs` | 逐拍全内存扫描。并行两路判据：**连续同向段** + **等间隔表**（stride 1~64 的等差数列覆盖率）。自动跳过噪声区；`--only-noisy` **反选**，专盯被跳过的那 34 MB 盲区（可跑 3 倍速） |
| `ShroudOracle.cs` | **会写内存**，谨慎。`find-screen`（找屏幕缓冲区）/ `noise`（测屏幕指标噪声底）/ `flags`（翻房子里的 0/1 开关）/ `scan`（逐页写反色）。屏幕指标 = 画面里纯黑的字节数，实测噪声底 0.9%，黑幕散开会是几十个百分点 |
| `longrun.py` | 两份全量快照的差分。按"齐整度"分三级（both / wipe / fill），带 `--require-before`、`--by-region`、以及**"邻居存活"**过滤（用来剔掉新分配的内存 —— 5.2 那个坑的解药） |

### ✅ 可以安全重复的协议（只读）

```powershell
# 拍一张全量快照（务必带 all）
tools\MemSnap.exe snap out.snap all
# 差分，只看"整片 FF 被改写、两边还留着 FF"的
python tools\longrun.py a.snap b.snap --min 16 --require-before 0xFF --by-region
```

### ❌ **会弄坏游戏的协议 —— 别再试**

| 做法 | 后果 |
| --- | --- |
| `ShroudOracle scan`：从"整页同值"的 30,034 个候选里逐页写反色 | **戳到第 50~75 页时游戏崩溃**（覆盖率才 1.9%） |
| `ShroudOracle flags`：翻 HouseClass 里"值是 0 或 1"的开关位 | 试射 100 个后**游戏报错**（用户手动重启） |

**结论：一个位置一个位置地戳，在真机上是拿用户的存档去赌一个必输的局。这条路已经封掉。**
