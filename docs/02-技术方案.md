## 1. 关键技术事实（全部实测，非推测）

| 事实 | 证据来源 | 对方案的意义 |
| --- | --- | --- |
| MO 3.3.6 使用的 `gamemd.exe` 是**原版 YR 1.001 (UC) 未改动二进制** | `D:\Mental Omega\syringe.log` 第 22 行：`Found Yuri's Revenge 1.001 (UC). Applying Ares 3.0.` | 数据结构与静态指针链**基本等同于原版 YR 1.001**，公开规律可作候选起点，无需从零逆向 |

## 3. 内存访问架构（核心策略）

### 3.1 只做外部读写，绝不注入

只使用这 5 个 API：

```
OpenProcess / ReadProcessMemory / WriteProcessMemory / VirtualQueryEx / EnumProcessModulesEx
```

**明确禁止**：`LoadLibrary` 注入、`CreateRemoteThread`、对 `.text` 段做代码 patch。
理由：MO 已被 Ares 打入 1450 个 hook，再改代码闪退风险极高；纯数据写入是唯一安全路径。

### 3.2 锁定而非赋值

游戏逻辑约 15 FPS，被修改的数值每帧被引擎重算。因此：

- 每个功能实现为一个**持续回写任务**，由 `CheatManager` 的**单一后台线程以 30 Hz** 串行驱动 `Tick()`。
- 单一线程串行执行，避免多线程同时写同一区域导致游戏崩溃。
- 后台线程 `IsBackground = true`，不阻塞退出。
- 每轮 `Tick` 用 `Stopwatch` 限速，超预算自动降频并记日志。

## 4. 地址定位三重保险

1. **AOB 特征码扫描**（支持 `??` 通配，模块内 + 全内存，分块多线程 + 可取消）：定位静态指针与锚点，抗小版本更新。
2. **静态指针链解析**：多级解引用，任一级失败即返回失败，**绝不返回脏地址**。
3. **运行时值校验**：用游戏界面可见值交叉验证。
   - 金钱：读到的值必须等于屏幕显示金额。
   - 电力：电力消耗字段必须等于界面显示的电力占用。
   - 选中：对象数量必须等于框选数量。
   - 校验失败 → 自动降级为重新扫描并记录日志。

结果持久化到 `<exe目录>\config\profile.json`，含 `exeCRC32`、`moduleBase`、指针链、字段偏移、校验指纹，可脚本化迭代，用户无需重复校准。

### 4.1 各功能实现思路与难度

| 功能 | 思路 | 难度 | 风险等级 |
| --- | --- | --- | --- |
| 金钱 | HouseClass 指针链 → 本地玩家 House → money 字段（4 字节 int）持续回写 | 低 | 🟢 低 |
| 电力 | 同一 HouseClass 内的产出 / 消耗字段，持续写（消耗置 0 或产出写大值） | 低-中 | 🟢 低 |
| 选中单位无敌 | 定位当前选中对象列表 → 写铁幕计时器大值 + 血量锁满；MO 还有力场盾机制需一并处理 | 高 | 🔴 高 |
| 秒杀敌人 | 遍历 TechnoClass 全局对象数组，按归属过滤，血量置 0，每 0.5 s 一轮 | 中-高 | 🔴 高 |
| 瞬间建造 | 定位生产队列进度 / 剩余时间字段，每帧清零 | 中 | 🔴 高 |
| 全图视野 | 定位地图 CellClass 数组的黑幕 / 迷雾数据区，分块批量清零 | 中-高 | 🟢 低 |

> 全图视野判为低风险的理由：黑幕与迷雾主要影响本机渲染。仍需实测确认。

## 5. 安全与稳定性约束

### 5.1 并发与容错
- 所有 RPM / WPM 返回值必须检查；失败时复核进程存活，已退出则进入"等待游戏启动"状态，不抛异常刷屏。
- 关键字段（血量、生产进度）写入后**立即回读校验**，不一致则重试一次并记录。
- 批量操作（清场、清黑幕）分块写入 + 块间 `Sleep`，避免瞬时大量写入造成卡顿或崩溃。
- **写入前用 `VirtualQueryEx` 确认目标页可写**，不可写则跳过并告警。
- 全程只写数据段与堆，绝不写游戏模块的只读 / 可执行页。

### 5.2 性能
- AOB 扫描为一次性操作，结果缓存到配置；扫描线程 `ThreadPriority.BelowNormal`，避免抢占游戏帧。
- 30 Hz Tick 每轮仅数十~数百次 4 字节读写，CPU 占用可忽略。
- 对象遍历限制为每 0.5 s 一轮，只读必要字段。

### 5.3 影响面控制
- 工具完全独立于游戏目录，除自身文件夹外**不改动 `D:\Mental Omega\` 下任何游戏文件**。
- 首次运行提示建议把游戏切为窗口化 / 无边框窗口（当前 `Windowed=False` 为独占全屏），否则修改器窗口会被覆盖；同时提供全局热键作为全屏兜底。

## 7. 关键接口契约

> 2026-09-29 按实际源码（`src\Cheats\CheatModels.cs`）改写。旧版本写的 `ICheat` 接口与
> `RiskLevel { Low, High }` 在代码中不存在。

```csharp
// 风险分级：注意是**三档**，比规划稿多一个"中"档
public enum SynchRisk { Low = 0, Medium = 1, High = 2 }

public enum CheatId
{
    Money = 0, PowerOutput = 1, SelectedInvincible = 2,   // S4 已实现并接入界面
    KillEnemies = 3, InstantBuild = 4, RevealMap = 5      // S6 未接线（枚举已定义，界面未注册）
}

// 功能用一个数据类描述，而不是接口实现
public sealed class CheatFeature
{
    public readonly CheatId Id;
    public readonly string Name;
    public readonly string Description;
    public readonly SynchRisk Risk;
    public readonly bool NeedsValue;      // 是否需要用户在界面上输入数值

    public FieldLocator Locator;          // 定位信息；null = 未校准
    public uint TargetValue;              // 界面显示值（写入时按 ValueScale 换算）
    public bool Enabled;                  // 是否持续锁定中
    public uint MinValue, MaxValue;       // 输入校验范围

    // 运行时状态（不落盘）
    public uint Address;                  // 0 = 未解析或解析失败
    public long WriteCount;               // 成功写入次数，界面用来证明"确实在工作"
    public uint LastSeenValue;            // 最近读到的游戏内数值
    public string LastError;              // "" 表示正常

    public bool IsCalibrated { get { return Locator != null && Locator.IsCalibrated; } }
    public bool IsActive     { get { return Enabled && IsCalibrated && Address != 0; } }
}

// 发动机：注册 + 绑定校准 + 30Hz 串行 Tick
public sealed class CheatEngine
{
    public CheatFeature Add(CheatFeature feature);   // 注册（必须先在 ApplyAll 里加执行分支！）
    public CheatFeature Find(CheatId id);
    public void BindProfile(CalibrationProfile profile);  // 校准完成后调用
    public void Start(); public void Stop();
}
```

**关键约束**：`IsCalibrated == false` 的功能，界面上必须置灰；
即使被强行开启，`ApplyAll` 也会跳过并清空地址。**绝不允许"开关能点、程序悄悄什么都不做"。**

```json
    "technoMaxHealth":  "0x0000007D",

  "map": { "shroudSize": "0x00000000" },
  "preferences": { "defaultMoney": 100000 }

```

要点：

- 定位有两种形态：**指针链**（`chain` / `chains`，多级解引用）或**静态地址**（`staticAddress`，
  相对模块基址的偏移，用于全局变量，跨会话恒定）。二者由 `hasStaticAddress` 区分。
- `chains` 是**候选链集合**，运行时逐条尝试，第一条失败自动回退下一条。
  实测主链 `0x683D4C` 多次会话 0 命中，全靠第 2 条 `0x4B4244,0x14C,…` 兜底 —— **不要只押一条**。
- **`calibrated == false` 即视为未校准**，对应功能自动禁用并提示去校准。
- `fieldOffsets` 里的 `0x00000000` **一律表示"未校准"**，不是"偏移就是 0"。

## 9. 联机同步的技术事实与对策

RA2/YR 是**帧同步（lockstep）确定性模拟**：每个客户端独立跑完整模拟，只交换指令，引擎周期性做 Sync Check 校验和比对，不一致即 out of sync 掉线。

| 风险等级 | 功能 | 原因 |
| --- | --- | --- |
| 🟢 低 | 金钱、电力、全图视野 | 视野/黑幕主要影响本机渲染；金钱可能不在校验和内，但会影响后续建造指令在他人客户端的资金校验，属**延迟性风险，需实测确认** |
| 🔴 高 | 选中无敌、秒杀敌人、瞬间建造 | 直接改动血量、生产进度等**参与同步校验**的状态，单方面修改必然掉线 |

**对策**：单人模式全开放；局域网友好模式默认只开低风险项；全员同步模式由房主 UDP 广播统一开关与目标值，**仅降低概率，不保证不掉线**。文档与界面必须如实标注：**公网 CnCNet 联机禁止使用**。
