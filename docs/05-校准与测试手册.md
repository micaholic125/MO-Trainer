# 05 校准与测试手册

> 版本 v1.0 ｜ 建立 2026-09-20
> 面向对象：**开发者与需要配合实测的用户**

---

## 1. 为什么需要校准

修改器需要知道"游戏把金钱放在内存的哪个位置"。不同 MO 版本、不同补丁可能改变数据结构，因此地址**不能凭公开资料直接写死**，必须在本机真机上通过"输入界面可见数值 → 内存搜索 → 触发数值变化 → 收敛"的方式定位，并做运行时校验。

校准一次后结果持久化到 `<工具目录>\config\profile.json`，之后长期可用。

---

## 2. 校准前置条件

1. 游戏已启动并**进入一局单人遭遇战**（不要停在主菜单，主菜单没有 HouseClass 数据）。
2. 游戏设置为**窗口化或无边框窗口**，方便与修改器窗口来回切换。
   - 当前 `D:\Mental Omega\RA2MO.ini` 中 `[Video] Windowed=False`（独占全屏），
     可在 MO 客户端设置里改为窗口化，或把该行改为 `Windowed=True`。
3. 修改器以管理员身份运行（manifest 已内置）。
   - **这条是硬性要求**：如果游戏是从管理员 PowerShell / 以管理员身份启动的，普通权限的修改器会在 `OpenProcess` 时被拒绝（`Win32=5 拒绝访问`）。界面会显示"连接失败：权限不足，请以管理员身份运行本程序"。
4. 校准过程中**不要暂停游戏**（数值需持续变化才能收敛）。

## 3. 校准操作流程（向导为六步）

| 步骤 | 向导提示 | 用户动作 |
| --- | --- | --- |
| 1 | 附加游戏 | 确认状态条显示"已连接"；未连接则启动游戏 |
| 2 | 定位金钱 | 在游戏里看当前金额（例：10000）→ 填进向导 → 点"开始搜索" |
| 3 | 触发变化 | 在游戏里**花掉一部分钱**（造个兵或卖个东西）→ 把新金额填进向导 → 点"筛选" |
| 4 | 重复筛选 | 重复第 3 步 2~3 次，直到候选只剩 1 个；点"锁定并校验" |
| 5 | 定位电力 | 在游戏里造一个耗电建筑（电力条变化）→ 按提示填入界面显示的电力数值 → 点"搜索" |
| 6 | 导出报告 | 点"导出校准报告"，把 `reports\calibration-*.txt` 发回给开发者 |

### 定位的跨会话复验（2026-10-07 起，硬规矩）

**"当天验证通过" ≠ "定位正确"。** 真机两次实测（2026-09-27、2026-10-07）：
保存下来的"名单指针格"其实是**代码段里的字节**（那几个字节的值恰好等于当场的数组地址），
当天读什么都对、换一局就失效 —— 而当天的一切校验全是"通过"。

因此，凡是"**格子 → 数组**"型定位（存一个位置、从它读出实际地址），**固化前必须过两关**：

1. **本局验证**：找到后当场读出真实内容（对象数、阵营分布等）—— 即现有流程；
2. **跨会话复验**：**换一局（新进程）后仍能照常读出**，才算校准成功。

配套约束（已写进代码与自检）：

- 候选"格子"必须落在**可写、不可执行**的内存里（`TechnoArrayFinder`，2026-10-07 加固）——
  真指针格是游戏会持续更新的全局变量，必然在可写数据段；
- 自检含专门断言"可执行页里的「格子」被排除"，该断言经"删掉检查即转红"验证过；
- 「自动查找总名单」保存后的界面文字会明确提示"本局可用 ≠ 已固化"。

### 敌我判据（秒杀敌人用）：金钱锚定（2026-10-07 起）

**问题**：秒杀敌人要写血量，写错对象的后果是"把自己人一起清空"。而此前唯一的敌我判据是配置里
**人工试出**的阵营偏移（`+0xF0`）——真机数据里它读出 `0x00010000` / `0x00010001` 这类
"既不像指针、又和用户实际单位数对不上"的值，**没有任何自动校验**。拿它直接写血量不可接受。

**做法**（`src\Cheats\TechnoOwnership.cs`）：用金钱当锚点，反查出真正的阵营字段。

1. **锚定**：从"你选中的单位"（游戏里能选中的必然是自己人）里逐 4 字节找指针 P，
   使 `*(P + 0x30C)` 正好等于当前金钱值 —— 这个 P 就指向我方 HouseClass，
   它所在的偏移就是**货真价实的阵营字段**（判据与无敌的归属校验同源，2026-09-22 起真机验证过）。
   偏移必须对**所有**样本对象都成立（取**交集**）：只在一个对象上成立的偏移不算数
   （同类对象在内存里挨着摆，一个对象的 0x1000 扫描窗口很容易扫到邻居对象的同名字段）。
2. **分类**：`字段值 == 我方 House 地址` → 我方；`0` → 归属不明（跳过）；其余 → 敌方。
3. **两道闸**：
   - ① **开启时安全抽检**：抽 128 个"判为敌方"的对象，逐个确认它们**没有连着我方 House**
     （复核对的是"我方 House 的具体地址"，不是金钱值 —— 开局各家金钱可能相同，用金钱复核会被巧合骗到）。
     按真机规模（千人名单里混百个自己人），漏检概率约百万分之二；
   - ② **"我方 0 个即拒绝"**：锚点一旦失效，全场都会被判成敌方（包括自己），此时必须一个字节都不写。
4. **会话级缓存**：锚点缓存 30 秒，并借"你选中的单位"周期复核；游戏（重新）连接时全部作废
   （跨会话的旧地址会落到别的对象上 —— 这是最危险的一类 bug）。
5. **执行节奏**：整场遍历较重，按 **0.5 秒/拍**执行、单拍写入上限 256（真机规模约 2 秒清完一轮，
   符合"3 秒内归零"的验收标准）；血量已经是 0 的目标不再重复写（否则前排"尸体"会吃光单拍额度）。

**已知残余风险（如实记录）**：
- 抽检只覆盖"判为敌方的对象里的前 128 个"与每个对象开头的 `0x1000` 字节；极端个例可能漏网；
- 判据依赖"我方 House 的金钱值可由金钱链读出"（金钱不可用时秒杀拒绝执行，属预期行为）；
- 配置里那个 `fieldOffsets.technoOwner`（人工试出值）**引擎已不再使用**；
  「高级功能」页的阵营分析仍会写它，仅作参考值保留。

**真机验证流程（下次开局）**：
1. 在游戏里**选中一个自己的单位**（多选几个更好）；
2. 「高级功能」→「预演：秒杀敌人（不写入）」→ 核对三处：**我方锚点**（偏移与 House 地址）、
   **将击杀 / 放过我方**两个数字、**安全抽检：通过**；
3. 数字合理 → 回「功能开关」页 → 勾选知情确认 → 打开「秒杀敌人」；
4. 观察敌方是否成片倒下、**自己的部队是否毫发无损**；有任何异常立刻关掉并导出日志。

### 第 8 部分：指针回溯与校准向导（S3 模块，无需游戏在跑）

用"合成内存"冒充游戏：一块 RW 内存充当模块映像（内含指向堆对象的静态指针），另一块充当堆对象（内含金钱、电力字段），
于是整套校准逻辑可以在没有游戏的情况下端到端跑通。

| 检查 | 通过标准 |
| --- | --- |
| 指针回溯 | 能把绝对地址反推成唯一静态路径（如 `[0x20000000+0x100]+0x30`）；该路径能解析回原地址；**没有静态指针指向的地址必须返回 0 条路径**（防止给出假配置）；留下逐层轨迹 |
| 金钱定位 | 首轮扫描收敛到唯一候选 → 写入测试值生效 → 确认后锁定指针链 → **测试值自动还原** → 链能解析回原字段 |
| 电力定位 | 基准记录成功；第一轮差分得到 2 个候选（超大值被过滤）；第二轮收敛到唯一字段；同样拿到静态指针链 |
| 消费检验 | 权威字段：消费后从测试值扣减 → 通过并锁链、自动还原原值；影子字段：消费后回落到原值附近 → **被识别并排除**，退回重新定位 |
| 电力反向差分 | 拆掉耗电建筑（数值回落）后仍保留真实字段 |
| 收尾 | 进入完成状态；校准报告生成且含环境/金钱/电力三部分；保存的配置可被重新加载 |
| 失败路径 | 排除候选后退回输入步骤；**未连接游戏时向导拒绝开始** |

### 真机实测到的关键事实（2026-09-21，MO 3.3.6 / gamemd.exe）

| 事实 | 数值 | 用途 |
| --- | --- | --- |
| 本玩家 House 对象与金钱字段 | 金钱 = `House + 0x30C`（三次会话一致） | 电力的偏移见下条 |
| **电力产出 = `House + 0x53A4`** | 与金钱相距 **0x5098** 字节（约 20KB） | 所以"金钱 ±8KB 窗口"必然搜不到 |
| **指针回溯上限 = 0x400** | 字段在对象内偏移超过 0x400 时，指向该对象的全局指针落在搜索范围外 → **回溯 0 命中** | 改用"金钱链 + 相对偏移"推导 |
| 电力数值编码 | `4 字节 ×1` 正确（搜 60 得 47745 个候选，按 260 筛选后收敛到 1 个） | 编码自动探测机制保留，用于其它字段 |
| **选中数量是全局变量** | 实测 = 模块基址 + `0x68ECC8`（绝对地址 `0x00A8ECC8`），**不在任何对象里** | 所以"往金钱对象附近找"永远找不到；必须把搜索范围扩到模块 `.data` |
| **数值搜索要覆盖 `.data`** | `HeapRegions` 只含私有页（`IncludeImage = false`），模块的 `.data` 是 image 类型、会被整体排除 | 若目标是全局变量，搜索范围再大也搜不到 |
| **选中列表的槽位** | 数组指针槽 = 模块基址 + `0x68ECA4`（绝对地址 `0x00A8ECA4`），距数量字段 **−0x24** | 2026-09-27 由 `+0x68ECA0` 修正而来。**注意：−0x24 并不符合经典 `DynamicVectorClass` 的 `{ 指针, 容量, 数量 }` 布局（那应是 −8）**，机制待查清，不要拿旧假设去推断别的字段 |
| **挨打必须先取消选中** | 游戏中让某单位挨打，需取消选中 → 换单位强制攻击 → 再选回来 | 选中列表内容会中途变化，**第 3 步必须每次现读选中列表、并对所有选中单位一起比对** |
| **只采样"当前选中的对象"采不到受害者** | 受害者按流程必须取消选中，一旦取消就再也不会被采样 —— 58 次采样一个字节都没动 | **跟踪集合只增不减**：见下表 |
| **电力字段权威性** | ✅ **已真机验证（2026-09-21）**：写入 30000 后游戏显示 `电力 = 30000`、电力条全绿不降 | 锁定电力有效 |
| **金钱链跨会话稳健性** | ✅ **已真机验证**：三次会话地址 `0x27EAAF24` / `0x27E8674C` / `0x27E86F24` 各不相同，链每次都解析成功 | 多候选链 + 同对象推导两层兜底有效 |
| 指向 House 的静态全局（会话 1） | `0x00A83D4C` | 见下条的会话差异 |
| 指向 House 的静态全局（会话 2） | `0x008B58B4`、`0x00A81984`、`0x00A83D4C`、`0x00A84CE0`、`0x00A853D0` | |
| **静态根会随会话变化** | 会话 1 只找到 1 个，会话 2 找到 5 个 | **必须保存多条候选链并在运行时回退**，不能只押一条 |
| 金钱字段权威性 | 消费检验通过（777777 消费 120 后读回 777657） | 金钱定位方案有效 |

**金钱测试值（2026-09-21 起）**：不再写死 `777777`，改为 **`当前金额 + 12345`**。
MO 的金钱显示是平滑滚动的，目标值离当前值越远滚得越久，旧写法会让用户干等。
消费检验门槛相应放宽为 **"原值 + 增量的 1/4"**（旧写法是原值与测试值的中点，
增量变小后会误判，必须一起改）。

**电力定位方式（2026-09-21 起）**：用户读数精确匹配 ——
游戏界面同时显示「电力」与「负载」的具体数值，用户读出来填进向导，然后在**整个游戏内存**里精确匹配并逐轮收敛。
差分方式已废弃：它会把"累计消费 / 建造计数"这类只增不减的字段选进来（实测选出过数值 11361 的伪字段）。

**同对象字段的链推导（2026-09-21 起）**：字段与金钱同属一个对象、但对象内偏移超过回溯上限 `0x400` 时，
直接指针回溯必然 0 命中。此时改为**用金钱链加上实测出的相对偏移**推导：

```
金钱链      : [0x683D4C] + 0x30C
相对偏移    : 0x5098                （电力地址 − 金钱地址，实测）
推导出的链  : [0x683D4C] + 0x53A4   （0x30C + 0x5098）
```

附带好处：直接继承金钱链的 8 条候选链，跨会话的稳健性一并拿到。推导来源会写进配置 `note` 便于日后排查。
哪种能搜到就用哪种，并把结果写进配置（`valueWidth` / `valueScale`）：

| 编码 | 含义 |
| --- | --- |
| 4 字节 ×1 | 普通 `int`，显示值 = 存储值 |
| 2 字节 ×1 | `short`；按 4 字节比时高 2 位是邻居数据，必然搜不到 |
| 4 字节 ×10 / ×100 | 模组为做小数级微调而放大存储 |
| 2 字节 ×10 / ×100 | 同上，且为 `short` |

若某编码搜到的候选在下一轮按值筛选中全部落空，判定编码猜错，自动换下一种重搜。

**基准结果（2026-09-21）**：84 项通过 / 0 项失败 / 2 项环境提示（非管理员、游戏附加被拒）。

## 5. 联机测试注意事项

1. **只在局域网自建房间测试**，绝不进公网 CnCNet。
2. 测试顺序：先只开 🟢 低风险项（金钱 / 电力 / 全图视野）观察 5 分钟是否会 out of sync → 再单独开某一项 🔴 高风险项，记录多久掉线。
3. **每次只测一项**，便于归因。
4. 记录内容：开的哪项、持续多久、是否弹 out of sync、是否被踢、日志文件名。
5. 结论必须如实写入文档，**不得写"保证不掉线"**。

## 6. 故障排查

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 编译报 `CS0016: 未能写入输出文件` | 修改器正在运行，exe 被系统锁住 | 直接重跑 `build.ps1` 即可：**脚本会先关掉正在运行的修改器，再发布到同一路径**（校准数据已落盘，关窗口不丢东西）。若想让它拒绝而非自动关闭，加 `-NoKill`。**旧版会另存成 `.new.exe` 的行为已永久移除，不要再找那个文件** |
| 状态条显示"连接失败：权限不足" | 游戏以管理员启动，修改器权限更低 | 右键修改器 → 以管理员身份运行 |
| 状态条一直"未运行" | 游戏没启动，或修改器权限低于游戏 | 用管理员身份运行修改器 |
| 状态条"已连接"但读值全是 0 | 校准失效，或不在对局中 | 重新校准；确认已进入对局 |
| 基址不是 `0x400000` | 游戏被其他工具重定位 | 记录日志并反馈，需要在定位时使用实际基址 |
| 开启后数值闪一下就恢复 | 刷新频率不足或地址错误 | 检查日志中的写入校验失败记录；重新校准 |
| 开启后游戏卡顿/闪退 | 写入频率过高或误写只读页 | 立即关闭该项，导出日志反馈 |
| 校准搜索候选筛不掉 | 输入的数值不对，或数值类型不是 4 字节整数 | 确认游戏内数值与输入完全一致 |
| 游戏切窗口化后画面异常 | ddraw 渲染器兼容问题 | 改用无边框窗口模式 |
