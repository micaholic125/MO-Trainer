# 05 校准与测试手册

> 版本 v1.0 ｜ 建立 2026-09-20
> 面向对象：**开发者与需要配合实测的用户**

---

## 1. 为什么需要校准

修改器需要知道"游戏把金钱放在内存的哪个位置"。不同 MO 版本、不同补丁可能改变数据结构，因此地址**不能凭公开资料直接写死**，必须在本机真机上通过"输入界面可见数值 → 内存搜索 → 触发数值变化 → 收敛"的方式定位，并做运行时校验。

校准一次后结果持久化到 `<工具目录>\config\profile.json`，之后长期可用。

---

## 2. 校准前置条件

1. 游戏已启动并**进入一局单人遭遇战**（不要停在主菜单，主菜单没有 HouseClass 数据）。
2. 游戏设置为**窗口化或无边框窗口**，方便与修改器窗口来回切换。
   - 当前 `D:\Mental Omega\RA2MO.ini` 中 `[Video] Windowed=False`（独占全屏），
     可在 MO 客户端设置里改为窗口化，或把该行改为 `Windowed=True`。
3. 修改器以管理员身份运行（manifest 已内置）。
   - **这条是硬性要求**：如果游戏是从管理员 PowerShell / 以管理员身份启动的，普通权限的修改器会在 `OpenProcess` 时被拒绝（`Win32=5 拒绝访问`）。界面会显示"连接失败：权限不足，请以管理员身份运行本程序"。
4. 校准过程中**不要暂停游戏**（数值需持续变化才能收敛）。

## 3. 校准操作流程（向导为六步）

| 步骤 | 向导提示 | 用户动作 |
| --- | --- | --- |
| 1 | 附加游戏 | 确认状态条显示"已连接"；未连接则启动游戏 |
| 2 | 定位金钱 | 在游戏里看当前金额（例：10000）→ 填进向导 → 点"开始搜索" |
| 3 | 触发变化 | 在游戏里**花掉一部分钱**（造个兵或卖个东西）→ 把新金额填进向导 → 点"筛选" |
| 4 | 重复筛选 | 重复第 3 步 2~3 次，直到候选只剩 1 个；点"锁定并校验" |
| 5 | 定位电力 | 在游戏里造一个耗电建筑（电力条变化）→ 按提示填入界面显示的电力数值 → 点"搜索" |
| 6 | 导出报告 | 点"导出校准报告"，把 `reports\calibration-*.txt` 发回给开发者 |

### 游戏版本指纹（2026-10-08 晚起，运行时强制检查）

配置里所有地址都是在一份**具体的 `gamemd.exe`** 上校准出来的。换一份引擎二进制（别的尤里复仇补丁、
汉化版、被人改过的 exe），内部结构可能变 —— 那时程序**不会报错**，只会照旧往"它以为是金钱"的地方写。
这是最坏的一类失败：**看起来在正常工作，实际在破坏别的内存**。

做法（`src\Core\EnvironmentCheck.cs`）：取游戏主程序文件的 **CRC32**（本工程文档里记的
`0x1B499086` 就是这个口径）与校准文件里的记录比对：

| 结论 | 行为 |
| --- | --- |
| 校准文件里**没记过** | 把当前这份**记上**（日志写明，并存进 `profile.json` 的 `exeCrc32`）|
| **一致** | 放行（日志一行）|
| **不一致** | **停用全部写入功能**：状态条显示「⚠ 游戏版本不符」，每张功能卡片上写明原因，日志记 ERROR。只读探测照旧（便于判断问题在哪）|

**遇到"版本不符"怎么办**：① 换回原来那个游戏版本（最稳）；或 ② 在这台机器上**重新跑一次「校准向导」**
（重新校准后，指纹会按当前这份 exe 重新记录）。**不要**在版本不符的状态下强行开功能 —— 程序也不会让你开。

**为什么不用"内存里代码的哈希"**：Ares/Syringe 会在运行时往代码里打 1450 个 hook，代码区每次都不同；
而**文件本身**稳定、可核对（本程序只读它，绝不写）。

### 电力 B 方案的判定：`+0xD0` 试探（2026-10-09 起）

**背景**：电力那条老路（锁 `House + 0x53A4`）2026-09-22 就被真机推翻 —— 那只是**界面显示值**：
写进去界面显示 30000，游戏仍判"电力不足"。B 方案要改**发电厂自己的产出**。

**离线分析结果（`开发日志/2026-10-09.md` 第三节）**：把 4 份采集报告的"电力跳变点"与"同秒变化的字段"交叉比对，
两次**独立**会话都指向建筑对象的 `+0xD0`（电厂建成时 `1 → 100`）；但同一偏移在步兵对象上有不相干的值在跳 ——
**采集报告只记"变化过的字段"，离线到此为止**。

**判定办法**：「高级功能」页的「**电力试探（点两次）**」按钮 —— 全程序**唯一**会往游戏里写实验值的地方：

1. 先在游戏里选中**你自己的一个单位** → 点「预演」（建立"我方锚点"，试探要它来确认"这是你的建筑"）；
2. 点选**你自己的一座发电厂**；
3. 点「电力试探」**两次**（第一次只给说明与警告）；
4. 程序往那座电厂的 `+0xD0` 写一个试探值（5000），**约 4 秒内**连续读界面上的电力产出，然后**无条件还原**；
5. 判定：**写中读数跟着试探值涨、还原后回落 ⇒ 这个字段就是产出来源**；否则不是。

**安全设计**：只作用于你自己选中的那一座建筑；写前查可写页；写后回读校验；`finally` 里无条件还原并回读确认；
试探值只存在约 4 秒；**试探期间不要关程序**。

### 定位的跨会话复验（2026-10-07 起，硬规矩）

**"当天验证通过" ≠ "定位正确"。** 真机两次实测（2026-09-27、2026-10-07）：
保存下来的"名单指针格"其实是**代码段里的字节**（那几个字节的值恰好等于当场的数组地址），
当天读什么都对、换一局就失效 —— 而当天的一切校验全是"通过"。

因此，凡是"**格子 → 数组**"型定位（存一个位置、从它读出实际地址），**固化前必须过两关**：

1. **本局验证**：找到后当场读出真实内容（对象数、阵营分布等）—— 即现有流程；
2. **跨会话复验**：**换一局（新进程）后仍能照常读出**，才算校准成功。

配套约束（已写进代码与自检）：

- 候选"格子"必须落在**可写、不可执行**的内存里（`TechnoArrayFinder`，2026-10-07 加固）——
  真指针格是游戏会持续更新的全局变量，必然在可写数据段；
- 自检含专门断言"可执行页里的「格子」被排除"，该断言经"删掉检查即转红"验证过；
- 「自动查找总名单」保存后的界面文字会明确提示"本局可用 ≠ 已固化"。

**"命中选中单位"只数数组自己的元素（2026-10-08 晚修）**：查找器判"这张名单里有没有你选中的单位"时，
读取窗口是 4096 项（16 KB），**远超大多数候选数组的长度**——旧实现数的是整个窗口，
于是数组**后面**的内存里凡有字节等于选中单位地址都会被算成命中（单位彼此引用很常见），
结果**每张候选都显示"命中 6/6"**、真假再也分不出来。真机 16:46 由此选中了一张只有 60 个对象、
玩家的 6 个单位一个都不在里面的假名单。现在只数**校验通过的 valid 个元素**；
自检含"数组之后的内存里引用着线索也不算"一条，经"退回旧写法即转红"验证过。
（同类教训与"抽检窗口 0x1000→0x400"同源：**读窗口必须贴合对象/数组自己的边界**，窗口开大了就会把邻居算成自己。）

### 敌我判据（秒杀敌人用）：金钱锚定（2026-10-07 起）

**问题**：秒杀敌人要写血量，写错对象的后果是"把自己人一起清空"。而此前唯一的敌我判据是配置里
**人工试出**的阵营偏移（`+0xF0`）——真机数据里它读出 `0x00010000` / `0x00010001` 这类
"既不像指针、又和用户实际单位数对不上"的值，**没有任何自动校验**。拿它直接写血量不可接受。

**做法**（`src\Cheats\TechnoOwnership.cs`）：用金钱当锚点，反查出真正的阵营字段。

1. **锚定**：从"你选中的单位"（游戏里能选中的必然是自己人）里逐 4 字节找指针 P，
   使 `*(P + 0x30C)` 正好等于当前金钱值 —— 这个 P 就指向我方 HouseClass，
   它所在的偏移就是**货真价实的阵营字段**（判据与无敌的归属校验同源，2026-09-22 起真机验证过）。
   偏移必须对**所有**样本对象都成立（取**交集**）：只在一个对象上成立的偏移不算数
   （同类对象在内存里挨着摆，一个对象的 0x1000 扫描窗口很容易扫到邻居对象的同名字段）。
2. **分类**：`字段值 == 我方 House 地址` → 我方；`0` → 归属不明（跳过）；其余 → 敌方。
3. **五分类 + 三层保护（2026-10-08 新增中立保护、当晚再加友军保护）**：按归属把名单里的对象分成五类 ——
   **我方 / 友军（不杀）/ 可击杀 / 疑似中立（不杀）/ 归属存疑（不杀）**：
   - **疑似中立**：归属的"房子"存在、但它的**金钱读数恒为 0**（中立 / 民用建筑通常如此）→ **绝不杀**；
   - **友军**：用户**手动标记过**的阵营（见下条"标记友军"）→ **绝不杀**。
     **这一档非有不可**：秒杀的判据原本只有"不是你 + 阵营有钱"，它**不知道"同盟"** ——
     AI 队友 / 局域网里的人类队友恰好符合那两条，会被一起清掉，而这类误伤**不可逆**；
   - **归属存疑**：归属值**不像真阵营**（指向代码区、小整数、读不出金钱）→ **绝不杀**
     （真机实测：178 个"敌方"里有 13+2 个是这类垃圾归属）；
   - 引擎与「预演」共用同一份分类实现（`TechnoOwnership.ClassifyOwners`），
     **预演上看到的数字 = 真正开杀时的名单**。

   **标记友军（有队友的局必须先做）**：游戏里**点选队友的任意一个单位或建筑** →
   修改器「高级功能」页点「**标记友军（不会杀）**」。效果与"疑似中立"同一层：
   该阵营从此不参与秒杀。三条注意：
   - **每开一局要重新标记一次**（阵营地址每局重新分配，程序不跨局沿用 ——
     游戏重连时会把标记清空并**在日志里明确写一行警告**）；
   - 标记前需要先建立过"我方锚点"（**先在游戏里选中自己的一个单位点一次「预演」**即可）——
     读阵营字段用的偏移来自那一步，程序不猜；
   - 误标记一个敌人的后果只是"**少杀**"（方向安全）；验证办法：再点一次「预演」，
     上面会多出「**友军不杀：N 个**」这一项。
4. **安全抽检 + "我方 0 个即拒绝"**：① 抽 128 个"可击杀"的对象，确认其中没有**连着我方 House 的**；
   ② 每一拍再数一遍：**我方对象一个都没有 = 锚点已失效**（比如换了局），此时全场都会被判成敌方（包括自己），
   必须拒绝执行、一个字节都不写。
   复核的扫描窗口取 **0x400**（**不要调大**）：真机实证 —— 同类对象在内存里紧挨着摆（间距约 0x708），
   扫 0x1000 会把"后方 3.6KB 处的自己人"算成"它自己"，导致**误报**、把正确的分类拦下
   （真机原话：被判为敌方的 0x2856C008 其实连着你方 House —— 而你的单位 0x2856CE18 就在它后面 0xE10 字节处）。
5. **会话级缓存**：锚点缓存 30 秒，并借"你选中的单位"周期复核；游戏（重新）连接时全部作废
   （跨会话的旧地址会落到别的对象上 —— 这是最危险的一类 bug）。
6. **执行节奏**：整场遍历较重，按 **0.5 秒/拍**执行、单拍写入上限 256（真机规模约 2 秒清完一轮，
   符合"3 秒内归零"的验收标准）；血量已经是 0 的目标不再重复写（否则前排"尸体"会吃光单拍额度）。

**已知残余风险（如实记录）**：
- 抽检只覆盖"判为敌方的对象里的前 128 个"与每个对象开头的 `0x1000` 字节；极端个例可能漏网；
- 判据依赖"我方 House 的金钱值可由金钱链读出"（金钱不可用时秒杀拒绝执行，属预期行为）；
- 配置里那个 `fieldOffsets.technoOwner`（人工试出值）**引擎已不再使用**；
  「高级功能」页的阵营分析仍会写它，仅作参考值保留。

**真机验证流程（下次开局；2026-10-08 晚更新 —— 改成"两次选中"）**：

> **为什么是两次选中**：心灵终结里**中立单位无法和友军单位同时选中**
>（2026-10-08 用户实测：点中立单位时友方单位会被取消选中）。
> 所以"把自己的单位和一座中立建筑一起框起来"这条路走不通 —— 改成分两次：
> **先选中自己的东西把锚点建起来，再单独点要看的那座中立建筑。**

1. 在游戏里选中 **3~5 个自己的单位 + 一座自己的建筑（比如发电厂）**；
2. 「高级功能」→「**自动查找总名单**」→ 只有当两条**硬验收**都过才会保存：
   ① 你选中的单位**全部**出现在名单里；② 「阵营」分布聚集成群（少数几种、各自一大群）。
   不通过就**不会保存**并会说明原因 —— 把那段文字发回给开发者；
3. 点「扫描全对象数组」核对：**交叉验证应为 N/N**、**阵营分布应为"少数几个阵营、各自聚集大量单位"**；
4. 「预演：秒杀敌人（不写入）」→ 核对四处：
   **我方锚点**、**将击杀 / 放过我方 / 疑似中立（不杀）/ 归属存疑（不杀）**四个数字、
   **"你选中的对象逐个判定"**（你的单位与建筑应显示 = 我方）、**安全抽检：通过**；
5. **（看中立建筑）** 保持修改器开着，回游戏里**只点那座中立建筑**，再点一次「预演」——
   这次上面会写「**沿用本次会话此前建立的锚点**」（因为选中的东西里没有你自己的单位），
   然后在"你选中的对象逐个判定"里看它：应显示 **疑似中立（不会杀）**
   （或显示"敌方（会被杀）"—— 那就是真敌方的东西，本来就该杀；显示"不在全对象名单里"说明名单不对，先别开杀）。
6. **（有队友的局）标记友军**：分别**点选每一位队友的任意一个单位** →
   回「高级功能」页点「**标记友军（不会杀）**」→ 再点一次「预演」，
   确认上面出现「**友军不杀：N 个**」（数量应与队友场上的东西对得上）。
7. 数字合理 → 回「功能开关」勾选确认后开启，观察敌方成片倒下、**自己的部队、中立建筑与队友毫发无损**；
   有任何异常立刻关掉并导出日志。

> **沿用旧锚点的两道保险**（2026-10-08 晚新增，防止"拿旧结论认人"）：
> ① 锚点记录的房子必须仍是**金钱链此刻指向的那个房子**（换了局即作废并清掉）；
> ② 分类之后还要核对**名单里至少有一个我方对象**（你自己的部队永远在场上）——
> 不满足就**不做任何判定**并提示重新建立锚点。

> 「选中读取」自 2026-10-08 起由共享件 `SelectionResolver` 统一提供（**金钱锚定 + 自动更正**）：
> 配置里的"选中列表槽位"只是起点，指向的对象里没有本方单位时会**自动更正**到正确的那张数组；
> 高级功能页 / 采集器 / 引擎用的是**同一套**实现（此前三份实现里有两份读出来的是垃圾，
> 真机 10-08 的"三次定位全败"就是这么被带偏的）。

## 4. 开发者自检（无需游戏在跑）

```powershell
# 编译 + 生成控制台自检程序 + 立即运行
powershell -NoProfile -ExecutionPolicy Bypass -File d:\AIWORK\XLZJ\build.ps1 -Test -RunTest
```

> ⚠️ **如果游戏是以管理员身份启动的，这条命令必须放在「管理员 PowerShell」里执行**，
> 否则第 6 部分会因权限不足被跳过（报告里是 WARN 而不是 FAIL）。
> 此时报告第一部分会显示 `进程权限 : 普通用户`。

自检项：

| 检查 | 通过标准 |
| --- | --- |
| 运行环境 | 进程为 x64；并显示当前是管理员还是普通用户 |
| 结构体布局 | `MEMORY_BASIC_INFORMATION` 在 x64 下为 48 字节、`MODULEINFO` 为 24 字节 |
| 日志系统 | 日志目录位于工具自身目录内，且未写入 C 盘 |
| 内存读写往返 | IntPtr 版与 uint 版双 API、16 位字节序、字节数组批量读写、写后回读校验全部一致 |
| 可写页校验 | 对只读映像页返回不可写，对新生数据页返回可写 |
| 自检进程区域枚举 | 能列出已提交区域且字段解析合理 |
| 游戏进程附加 | 游戏在运行时能取到基址 `0x00400000` 与模块大小 |
| 映像头读取 | 能在基址读到 `MZ`，并解析 `e_lfanew` 后在 PE 头读到 `PE` 签名 |
| 游戏进程区域画像 | 列出已提交 / 私有 / 可写区域数量与可写总量，并打印最大的私有可写区域 |

### 第 8 部分：指针回溯与校准向导（S3 模块，无需游戏在跑）

用"合成内存"冒充游戏：一块 RW 内存充当模块映像（内含指向堆对象的静态指针），另一块充当堆对象（内含金钱、电力字段），
于是整套校准逻辑可以在没有游戏的情况下端到端跑通。

| 检查 | 通过标准 |
| --- | --- |
| 指针回溯 | 能把绝对地址反推成唯一静态路径（如 `[0x20000000+0x100]+0x30`）；该路径能解析回原地址；**没有静态指针指向的地址必须返回 0 条路径**（防止给出假配置）；留下逐层轨迹 |
| 金钱定位 | 首轮扫描收敛到唯一候选 → 写入测试值生效 → 确认后锁定指针链 → **测试值自动还原** → 链能解析回原字段 |
| 电力定位 | 基准记录成功；第一轮差分得到 2 个候选（超大值被过滤）；第二轮收敛到唯一字段；同样拿到静态指针链 |
| 消费检验 | 权威字段：消费后从测试值扣减 → 通过并锁链、自动还原原值；影子字段：消费后回落到原值附近 → **被识别并排除**，退回重新定位 |
| 电力反向差分 | 拆掉耗电建筑（数值回落）后仍保留真实字段 |
| 收尾 | 进入完成状态；校准报告生成且含环境/金钱/电力三部分；保存的配置可被重新加载 |
| 失败路径 | 排除候选后退回输入步骤；**未连接游戏时向导拒绝开始** |

| **选中列表的槽位** | 数组指针槽 = 模块基址 + `0x68ECA4`（绝对地址 `0x00A8ECA4`），距数量字段 **−0x24** | 2026-09-27 由 `+0x68ECA0` 修正而来。**注意：−0x24 并不符合经典 `DynamicVectorClass` 的 `{ 指针, 容量, 数量 }` 布局（那应是 −8）**，机制待查清，不要拿旧假设去推断别的字段 |
| **挨打必须先取消选中** | 游戏中让某单位挨打，需取消选中 → 换单位强制攻击 → 再选回来 | 选中列表内容会中途变化，**第 3 步必须每次现读选中列表、并对所有选中单位一起比对** |

| 金钱字段权威性 | 消费检验通过（777777 消费 120 后读回 777657） | 金钱定位方案有效 |

**金钱测试值（2026-09-21 起）**：不再写死 `777777`，改为 **`当前金额 + 12345`**。
MO 的金钱显示是平滑滚动的，目标值离当前值越远滚得越久，旧写法会让用户干等。
消费检验门槛相应放宽为 **"原值 + 增量的 1/4"**（旧写法是原值与测试值的中点，
增量变小后会误判，必须一起改）。

**电力定位方式（2026-09-21 起）**：用户读数精确匹配 ——
游戏界面同时显示「电力」与「负载」的具体数值，用户读出来填进向导，然后在**整个游戏内存**里精确匹配并逐轮收敛。
差分方式已废弃：它会把"累计消费 / 建造计数"这类只增不减的字段选进来（实测选出过数值 11361 的伪字段）。

**同对象字段的链推导（2026-09-21 起）**：字段与金钱同属一个对象、但对象内偏移超过回溯上限 `0x400` 时，
直接指针回溯必然 0 命中。此时改为**用金钱链加上实测出的相对偏移**推导：

```
金钱链      : [0x683D4C] + 0x30C
相对偏移    : 0x5098                （电力地址 − 金钱地址，实测）
推导出的链  : [0x683D4C] + 0x53A4   （0x30C + 0x5098）
```

附带好处：直接继承金钱链的 8 条候选链，跨会话的稳健性一并拿到。推导来源会写进配置 `note` 便于日后排查。
哪种能搜到就用哪种，并把结果写进配置（`valueWidth` / `valueScale`）：

| 编码 | 含义 |
| --- | --- |
| 4 字节 ×1 | 普通 `int`，显示值 = 存储值 |
| 2 字节 ×1 | `short`；按 4 字节比时高 2 位是邻居数据，必然搜不到 |
| 4 字节 ×10 / ×100 | 模组为做小数级微调而放大存储 |
| 2 字节 ×10 / ×100 | 同上，且为 `short` |

若某编码搜到的候选在下一轮按值筛选中全部落空，判定编码猜错，自动换下一种重搜。

**基准结果（2026-09-21）**：84 项通过 / 0 项失败 / 2 项环境提示（非管理员、游戏附加被拒）。

## 5. 联机测试注意事项

1. **只在局域网自建房间测试**，绝不进公网 CnCNet。
2. 测试顺序：先只开 🟢 低风险项（金钱 / 电力 / 全图视野）观察 5 分钟是否会 out of sync → 再单独开某一项 🔴 高风险项，记录多久掉线。
3. **每次只测一项**，便于归因。
4. 记录内容：开的哪项、持续多久、是否弹 out of sync、是否被踢、日志文件名。
5. 结论必须如实写入文档，**不得写"保证不掉线"**。

## 6. 故障排查

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 编译报 `CS0016: 未能写入输出文件` | 修改器正在运行，exe 被系统锁住 | 直接重跑 `build.ps1` 即可：**脚本会先关掉正在运行的修改器，再发布到同一路径**（校准数据已落盘，关窗口不丢东西）。若想让它拒绝而非自动关闭，加 `-NoKill`。**旧版会另存成 `.new.exe` 的行为已永久移除，不要再找那个文件** |
| 状态条显示"连接失败：权限不足" | 游戏以管理员启动，修改器权限更低 | 右键修改器 → 以管理员身份运行 |
| 状态条一直"未运行" | 游戏没启动，或修改器权限低于游戏 | 用管理员身份运行修改器 |
| 状态条"已连接"但读值全是 0 | 校准失效，或不在对局中 | 重新校准；确认已进入对局 |
| 基址不是 `0x400000` | 游戏被其他工具重定位 | 记录日志并反馈，需要在定位时使用实际基址 |
| 开启后数值闪一下就恢复 | 刷新频率不足或地址错误 | 检查日志中的写入校验失败记录；重新校准 |
| 开启后游戏卡顿/闪退 | 写入频率过高或误写只读页 | 立即关闭该项，导出日志反馈 |
| 校准搜索候选筛不掉 | 输入的数值不对，或数值类型不是 4 字节整数 | 确认游戏内数值与输入完全一致 |
| 游戏切窗口化后画面异常 | ddraw 渲染器兼容问题 | 改用无边框窗口模式 |
| 界面按钮"挤成一堆"、压住旁边的说明文字 | 与 7.2 同理：**写死的坐标不随 DPI 缩放走**（2026-10-08 真机截图：「标记友军」压住提示文字、文字被窗口右缘切掉） | 位置改由**实测尺寸**算（`AdvancedPage.RelayoutAll`：按钮从左到右、放不下换行；提示各自单独占一行）。**自检已含排版断言**（560/820/1400/2380 四档宽度下控件互不重叠、不超出页面），改坏即转红 —— 本机复现不出来的问题靠它兜底 |
