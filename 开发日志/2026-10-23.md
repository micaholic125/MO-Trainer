## 遇到的问题

- **为什么日志看起来"每 3 秒一次"**：`MemoryIO.NoteFailure` 有 3 秒节流
  （`(now - _lastFailureLog).TotalSeconds < 3` 就直接返回），而失败实际发生在每次只读探测上
  （约 1 秒一拍），所以被节流成 3 秒一条。**节流掩盖了真实频率，也掩盖了来源**。
- **排除过的路径**：主链回退里的候选链 `[0x68022C, 0x0, …]` 也会读到 `0x3F800000`，
  但它只在**主链失败**时触发，且同一时刻必伴随"主链解析失败"那一行；
  10-23 那局 16 条失败附近没有回退行 ⇒ 不是它。真正的来源是瞬间建造的探测
  （失败行紧跟着"现在没有东西在造"可作旁证）。
- **本轮前两版判断**：先怀疑 `PeekTechnoArray` 读名单首项，后怀疑金钱展示读取；
  都被"失败频率与回退行/展示行不同步"排除。教训与 7.4 一致：**让日志里的数字说话，不要猜**。
- **Word 转换 HTML 时不认 CSS 里的图片宽度**：直接用 `style="width:620px"` 生成 docx，
  两张截图的原始宽度变成 1150pt / 766pt，远超 A4 可用宽（482pt），会冲出页面。
  治法是**先把 PNG 缩放到页面宽度的像素数（642 px @96dpi）再插入**，Word 按原生尺寸排；
  同时用 Word 把页边距统一成 2 cm。**不要依赖 HTML 的 width 属性**。
- **`--smoke` 在非管理员终端下会卡在 UAC 确认框**：本次为了不改交付 manifest，
  另编了一个 `asInvoker` 的临时副本（`dist\_devbuild\`，不入交付、不入库）来跑冒烟与截图；
  真交付的 exe 仍是 `requireAdministrator`。以后需要截图 / 冒烟也可以沿用这个办法。
- **Word 里按"句子片段"定位会插到句子中间**：S8-4 第一次给说明书补弹窗说明时，
  锚点是"建议把游戏设为窗口化"（只是那句话的前半段），`TypeParagraph` 就把段落从中间拆开、
  新说明和后半句黏在一起。**处置**：用 `git checkout -- docs\使用说明.docx` 恢复，
  改用**段尾整句**作锚点（"如果习惯全屏……（见第五节）。" / "写进去的可能是别的东西。"）重做，
  并核对前后段落的 `Style.NameLocal`（新 FAQ 的答案必须沿用"普通(网站)"，不能变成 note 样式）。
  教训：对用户可见的文档做程序化编辑，**锚点要落在段落边界**，改完必须读回前后两段，不能只看"找到了"。
- **用 `SendMessage(BM_CLICK)` 点会打开模态窗口的按钮会把测试脚本卡死**：
  按钮的点击处理里调 `ShowDialog`，消息同步派发，测试脚本一直等到对话框关闭才返回。
  **改用 `PostMessage`**（投递后立即返回）就正常。这是测试脚本的坑，与产品代码无关。
- **WinForms 的 Flat 勾选框用 `BM_GETCHECK` 读回 0**（即使界面上已勾选）：
  这次的真值以 `trainer.json` 的落盘结果 + 截图为凭据，**不要只信 `BM_GETCHECK`**。
