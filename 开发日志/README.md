# 开发日志说明

本目录按天记录本项目的开发进展，一天一个文件，命名 `YYYY-MM-DD.md`。

## 固定结构

```markdown
# YYYY-MM-DD 开发日志

## 今日完成
- [阶段编号] 事项 —— 验证方式

## 待办事项
- [阶段编号] 事项

## 遇到的问题
- 现象 → 原因 → 处理

## 下轮计划
- 从哪个阶段编号开始；需要用户配合的动作
```

## 规则

1. **只有已验证的事项才能写进"今日完成"**，并必须注明验证方式（编译通过 / 自检报告 / 用户实测）。
2. 未跑通的一律写进"待办事项"，并标注归属阶段编号。
3. 每轮收工同步更新 `docs/04-开发执行步骤.md` 的进度追踪表。
4. 日志只记录事实，不做主观评价。

### ⚠️ 引用历史日志里的**数值**时务必当心

早期日志里记录过的地址/偏移，有一部分**已被后续会话推翻或修正**，而历史文件按上面的约定不改写。
已知的例子：`2026-09-21.md` 里的「选中数量 = `0x00B08EC8`、模块 + `0x708EC8`、槽位 = 数量 − 8 字节」
**三个数都是错的**（正确值：`0x00A8ECC8`、模块 + `0x68ECC8`、槽位 `0x68ECA4` 即 −0x24）。

**判断某个地址现在是否有效，只看这两个地方**：

1. `dist\config\profile.json` 的 `locators` / `fieldOffsets`（**这是唯一权威**，且认 `calibrated` 标志）；
2. `证据归档\运行日志\` 里对应日期的原始日志。

历史日志的价值在于**记录当时的探索过程与结论演变**，不在于它里面的数字。
