### 十二、`[S4-3]` 电力：**实机达标** —— 同时抓出并修掉一个我自己写的 bug

**用户实机结果：通过。**（这一局：1 座建造厂 + 2 座电厂 + 1 座核电站）

**日志里的执行证据**（`证据归档/运行日志/power-realmachine-20261009.txt`）：
```
16:56:14  电力：已提升：NACNST×1（60→30000）、NAPOWR×2（150→30000）、NANRCT×1（2000→30000）
          ｜提升 3 个型号 / 4 座建筑｜本拍写入 3｜累计写入 3
16:56:20  电力：已提升：NACNST×1（30000→30000）、NAPOWR×2（30000→30000）、NANRCT×1（30000→30000）
          ｜提升 3 个型号 / 4 座建筑｜本拍写入 0｜累计写入 3      ← 幂等，不再重复写
16:57:25  电力已关闭：把 0 个型号的发电量改回原值                ← **这一行是 bug 的症状**
```

**发现的问题（我的 bug，必须说清楚）**：第一拍的原值记对了（`60→30000`），
**第二拍起就变成 `30000→30000`** —— 记账里的"原值"被我们自己写进去的值覆盖了，
于是关闭功能时 `还原 0 个`，**游戏会一直带着被放大的发电量**。

根因是 `PowerBoost.Apply` 里多写的一句：
```csharp
if (original != current) { original = current; _originals[typeAddress] = current; }
```
本意是"值被外部改动就重新同步"，**方向恰好写反了**：我们自己写完目标值之后，
下一拍 `current` 必然等于目标值、与原值不同，于是**每跑一拍就把原值覆盖一次**。

**为什么自检没拦住**：原来的断言只测"跑**一拍**就还原"，而真实引擎是**每秒跑一拍** ——
**场景少跑了两拍**，正好绕开了 bug。这是"测试场景不够贴近真实运行方式"的典型。

**修法与加固**
1. 删掉那句错误同步：**原值只记一次，写下之后不再被任何一拍修改**；
2. 断言改成**连跑三拍再还原**，并且**判据从"字段现值"改成"记账里的原值"**——
   后者才有鉴别力（有 bug 时前者照样成立）；
3. **改坏验证**：把那个 bug 原样放回去 → 两条断言**精确复现真机症状**
   （`记账里的原值 5000→5000`、`还原 0 个｜现值 5000`）；
   顺带发现并纠正了断言名在吹牛（叫"不会覆盖原值"、实际只验字段值）。
4. 另外修了一处**真机日志抓到的瞬时失败**（`16:56:53` 一次"认不出哪些建筑是我的，已拒绝执行"）：
   判据要比较"阵营的金钱"与"我此刻的金钱"，两次读不在同一瞬间，玩家正在花钱时就会对不上，
   一拍后自己恢复。已加 `AnchorMiss` 标记 + **重读金钱重试一次**（fail-closed 不变，只是别让它断续）。

自检 278 → **279 项通过 / 0 失败**；冒烟通过。**遗留**：新版本还没在真机上重跑一次"开→关→确认已还原"。
