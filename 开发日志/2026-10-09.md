### 一、「高级功能」页横向滚动条残留 —— 定位与修复（凌晨 00:0x）

**起因**：10-08 23:38 用户打开新版逐页点看时，日志里只有「高级功能」页报 `AdvancedPage 820x484 横条=有 竖条=有`，

**定位过程（全部用数字，不靠截图）**
1. 先让 `--smoke` **逐页走一遍并记录每页的滚动条状态**（原来只记当前那一页，所以"只有某一页出问题"这类情况一次都抓不到）——
   本机当场复现：`AdvancedPage 820x484 横条=有 竖条=有`。
2. 再给 `LogLayoutDiagnostics` 加一条：**页面出现横向滚动条时，把页内每个控件的实际位置写进日志**。
   真机数字（`[越界排查]`）：页内最宽控件右边界 770，而页面可用宽 794 —— **没有任何控件超出**。

**根因（连锁反应）**：内容比页面高 → 出现**竖向**滚动条 → 可用宽从 820 缩到 794（少 26 像素）→
先前按 820 排好的控件**瞬间超出** → **横向**滚动条跟着出现；等控件重新排好、早已装得下时，
**那根横向条却没人叫它退场**（`SizeChanged` 不会因为"客户区被滚动条挤小"而触发，所以重排也没发生）。
雪上加霜的是：输出框高度写死了 120 的下限，内容一高就必然顶出竖向条。

**修法（4 处）**

| # | 改动 | 作用 |
| --- | --- | --- |
| 1 | 输出框高度的下限由 **120 改为 60** | 空间不够时不再硬撑，页面宁可滚动也不连锁 |
| 2 | 排版末尾强制 `PerformLayout()` | 让滚动条的去留**重新判定**，残留的横向条自动退场 |
| 3 | 同时挂 `ClientSizeChanged`（原来只挂 `SizeChanged`）| 客户区因滚动条变窄时**也重排**，从根上不再"按旧宽度排" |
| 4 | 副标题缩短为一行（"秒杀 / 瞬间建造 / 全图视野 —— 本页只读不写。"）| 降低内容高度，让该页在 484 高度下**完全放得下** |

`AdvancedPage 820x484 **横条=无 竖条=无**`（其余各页仍为"横条=无"）；自检 **232 项通过 / 0 失败**；

### 九、自动巡检（本轮第二件事；把"一项一趟"改成"玩一局 + 点一次导出"）

**目标**（第七节结论四的落地）：剩余真机项原本是"开一局 → 在游戏里选中某个东西 → 点按钮 → 发日志"，
用户已连续配合 6 轮。把其中**能靠程序自己算的**做成自动的。

**新增 `Calibration\AutoInspection.cs`（只读，一个字节都不写）**，含两项：

**① 找「类型对象」**（电力 B 方案卡在这里）

关键的一段设计推理，**用真机数据否掉了一个想当然的做法**：
- 原本打算"按类型表分组 = 同一种建筑"来比对。查真机报告发现**不成立** ——
  类型表只有十来个（`116 / 64 / 23 / 16` 各一组），说明它对应的是 **C++ 类别**（所有建筑共用一个），
  **不是"电厂 / 兵营"这种型号**。按它分组，等于拿不同的东西当"同类"。
- 改用的判据（能在同一类别内部自己找出型号）：
  同一类型表内，某个偏移的**取值种数明显少于对象数** ⇒ 有多个对象共用同一个取值；
  共用得越厉害越像"同类共用一份的说明书"。再用**目标里有没有建造 ID 字符串（如 GAPOWR）**确认 ——
  那是 `PowerScout` 起就在用的、类型对象独有的特征。
- 排掉两个**必然会撞上**的假阳性：**偏移 0**（那是类型表本身，它"同类相同"必然成立）、
  **阵营指针**（同一方的建筑全指向同一个房子，共用程度也很高 —— 用"目标在 +0x30C 处读到的正好是你的金钱"把房子认出来）。

**② 主链反查**（`[S3]`）：主链 `0x683D4C → +0x30C` 在真机上早就 0 命中、一直靠候选链兜底。
现在从"金钱此刻真正落在的房子"（金钱地址 − `0x30C`）用 `PointerScanner` 反推静态根。

**`HarvestSession` 的三处增强**
1. **新出现的对象自动跟踪**（瞬间建造用）：用户**不必先选中**，程序自己盯"采集期间才冒出来的"对象。
   带**观察期**（连续活过 3 拍才转正）—— 战场上每秒都有大量子弹/碎片冒出来，
   不筛的话跟踪名额会被它们瞬间占满，真正要看的"正在造的那座建筑"一个都进不来。
2. **收尾阶段跑巡检**：放在**采样线程**里，不在界面线程 —— 主链反查是全内存扫描，要十几秒，
   放界面上等就是假死。界面照常转，只是按钮上多显示"正在收尾"。
3. **报告写两遍**：先落一版不含巡检的，巡检完再覆盖成完整的。
   理由：收尾要十几秒，用户完全可能在这期间把修改器关掉 —— 只写一次的话这一局就白玩了。
   写法也改成"先写临时文件再改名"，避免中途被打断留下**一份看起来完整、其实被截断的报告**。

**验证（全部通过）**
